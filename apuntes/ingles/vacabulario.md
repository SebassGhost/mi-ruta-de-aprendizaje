
# Estructuras de datos y Variables

• Array (Arreglo/Vector): Colección ordenada de elementos.
• Boolean (Booleano): Tipo de dato que solo puede ser true (verdadero) o false (falso).
• Character / Char (Carácter): Un solo símbolo, letra o número.
• Float / Double (Punto flotante): Números con decimales.
• Integer / Int (Entero): Números completos sin decimales.
• Object (Objeto): Instancia de una clase que contiene propiedades y métodos.
• String (Cadena de texto): Secuencia de caracteres.
• Value (Valor): El contenido real asignado a una variable.
• Variable (Variable): Espacio reservado en memoria para almacenar un dato cambiante.

## Lógica y Control de Flujo

• Branch (Bifurcación / Rama): Camino alternativo que toma el código según una condición.
• Condition (Condición): Expresión que se evalúa como verdadera o falsa para tomar una decisión.
• Else (De lo contrario): Bloque de código que se ejecuta si la condición principal if no se cumple.
• If (Si condicional): Estructura que ejecuta código solo si se cumple una condición.
• Loop (Bucle / Ciclo): Estructura que repite un bloque de código mientras se cumpla una condición.
• Nested (Anidado): Un bloque de código colocado dentro de otro (ej. un bucle dentro de otro bucle).
• Return (Retornar / Devolver): Termina la ejecución de una función y devuelve un resultado.
• Statement (Instrucción / Sentencia): Una línea de código individual que realiza una acción.
• Switch (Selector): Estructura de control que evalúa múltiples casos posibles para una variable.

## Funciones y Programación Orientada a Objetos (POO)

• Argument / Parameter (Argumento / Parámetro): Valores que se le pasan a una función cuando es invocada.
• Call / Invoke (Llamar / Invocar): Ejecutar una función o método.
• Class (Clase): Plantilla o molde para crear objetos.
• Constructor (Constructor): Función especial que inicializa un objeto recién creado.
• Encapsulation (Encapsulamiento): Ocultar los detalles internos de un objeto y mostrar solo lo necesario.
• Function / Method (Función / Método): Bloque de código reutilizable que realiza una tarea específica.
• Inheritance (Herencia): Mecanismo por el cual una clase adquiere propiedades de otra.
• Instance (Instancia): Un objeto concreto creado a partir de una clase.

## Desarrollo, Pruebas y Depuración

• Bug (Error / Fallo): Un error en el código que causa un comportamiento inesperado.
• Build (Compilar / Construir): Proceso de transformar el código fuente en un archivo ejecutable o listo para producción.
• Compile (Compilar): Traducir el código de alto nivel a lenguaje máquina.
• Debug (Depurar): Buscar y solucionar errores en el código.
• Deploy (Desplegar): Publicar o subir la aplicación a un entorno de producción (servidor) para que los usuarios la usen.
• Environment (Entorno): El contexto donde se ejecuta el código (ej. development, staging, production).
• Feature (Característica / Funcionalidad): Una nueva herramienta o parte que se añade al software.
• Log (Registro / Bitácora): Archivo o texto que registra eventos o errores ocurridos durante la ejecución.
• Run / Execute (Ejecutar): Poner en marcha el programa.
• Test (Prueba): Código escrito específicamente para verificar que otra parte del código funcione bien.

## Entornos, Redes y Bases de Datos

• API (Application Programming Interface): Interfaz que permite a dos aplicaciones comunicarse entre sí.
• Backend (Lado del servidor): La lógica, bases de datos y servidores que el usuario no ve.
• Database / DB (Base de datos): Sistema para almacenar y organizar grandes volúmenes de datos.
• Frontend (Lado del cliente): La interfaz gráfica y la parte visual con la que interactúa el usuario.
• Framework (Marco de trabajo): Conjunto de herramientas y reglas preestablecidas para desarrollar software más rápido.
• Library (Librería / Biblioteca): Colección de funciones o código preescrito que puedes importar a tu proyecto.
• Query (Consulta): Petición de información que se le hace a una base de datos.
• Request (Petición): Solicitud enviada por el cliente al servidor.
• Response (Respuesta): Información devuelta por el servidor al cliente.

## Git y Control de Versiones

• Commit (Confirmar cambios): Guardar una especie de "captura" o foto del estado actual del código con un mensaje explicativo.
• Merge (Fusionar): Unir dos ramas (branches) de código diferentes.
• Pull (Traer / Descargar): Descargar los últimos cambios del repositorio remoto al equipo local.
• Push (Subir / Enviar): Enviar los cambios locales al repositorio remoto (ej. GitHub).
• Repository / Repo (Repositorio): Carpeta o espacio donde se almacena todo el proyecto y su historial de cambios.

## Verbos de Acción (Lo que hace el código o nosotros mismos)

• To assign (Asignar): Guardar un valor dentro de una variable.
• To bind (Vincular / Enlazar): Conectar dos componentes o datos para que actúen juntos.
• To call / To invoke (Llamar / Invocar): Ejecutar una función.
• To clear / To wipe (Limpiar / Borrar): Eliminar los datos almacenados de una pantalla o memoria.
• To crash (Romperse / Colgarse): Cuando el programa deja de funcionar de golpe.
• To fetch (Traer / Buscar): Ir a buscar datos (normalmente a un servidor o base de datos).
• To handle (Manejar / Gestionar): Controlar una situación o un error en el código.
• To initialize (Inicializar): Darle su primer valor a una variable o arrancar un proceso.
• To parse (Analizar / Convertir): Convertir un formato de texto a uno que el código entienda (ej: de JSON a Objeto).
• To render (Renderizar / Dibujar): Pintar o mostrar la interfaz visual en la pantalla.
• To override (Sobrescribir): Reemplazar el comportamiento de una función heredada por uno nuevo.
• To trigger (Disparar / Activar): Iniciar una acción automáticamente debido a un evento (como hacer un clic).

## Adjetivos y Estados del Sistema

• Deprecated (Obsoleto): Código que aún funciona pero ya no se recomienda usar porque desaparecerá.
• Disabled (Deshabilitado): Algo que está apagado o no permite interacción (ej: un botón gris).
• Enabled (Habilitado): Algo activo y listo para usarse.
• Hardcoded (Escrito a fuego / Código duro): Datos guardados directamente en el código en lugar de usar variables o bases de datos (suele ser mala práctica).
• Legacy (Heredado / Antiguo): Código viejo que se sigue usando en la empresa y da soporte al sistema actual.
• Production-ready (Listo para producción): Código que ya está probado y es lo suficientemente estable para lanzarse al público.
• Responsive (Adaptable): Diseño web que se adapta correctamente a pantallas de celulares, tablets y computadoras.
• Thread-safe (Seguro para hilos): Código que puede ser ejecutado por múltiples procesos a la vez sin romperse.

## Frases útiles para usar en el día a día

1. Comentarios dentro del código e incidencias (Code & Tickets)

• "Fix temporary workaround for user login."  (Arreglar la solución temporal para el inicio de sesión).
• "TODO (es literalmente "to do" pero en el codigo se escribe en mayusculas y siempre junto): Refactor this function to improve performance."  (Por hacer: Reestructurar esta función para mejorar el rendimiento).
• "This variable cannot be null."  (Esta variable no puede ser nula).
• "The API returns a 404 status code."  (La API devuelve un código de estado 404).
2. Revisión de código de compañeros (Pull Requests / Code Review)

• "Can you please add a unit test for this edge case?"  (¿Puedes por favor agregar una prueba unitaria para este caso extremo?).
• "There is a typo in this variable name."  (Hay un error de dedo/ortografía en el nombre de esta variable).
• "This approach looks good, but it might cause a memory leak."  (Este enfoque se ve bien, pero podría causar una fuga de memoria).
• "LGTM! (Looks Good To Me) Merging now."  (¡Se ve bien para mí! Fusionando ahora).
3. Reuniones diarias de equipo (Daily Standup)

• "Yesterday, I worked on the payment gateway integration."  (Ayer trabajé en la integración de la pasarela de pagos).
• "Today, I will focus on fixing the layout bugs on mobile devices."  (Hoy me enfocaré en arreglar los errores de diseño en dispositivos móviles).
• "I am currently blocked by the backend API; I need the documentation."  (Actualmente estoy bloqueado por la API del backend; necesito la documentación).
• "I will sync with you after the meeting to resolve this."  (Me coordinaré contigo después de la reunión para resolver esto).
